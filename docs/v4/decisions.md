# v4 decision log: what was decided, the alternatives, and why

Continues `docs/v3/decisions.md` (D1–D26). "Pilot" = exploratory seeds 0–4; confirmatory seeds are 10–14.

| # | Decision | Alternatives considered | Why |
|---|---|---|---|
| E1 | Work on branch `v4-next-steps`, one PR, merge when everything is done and documented | Push to master | The user's instruction ("New branch + PR, merge when done"). |
| E2 | Freeze each part's pre-registration in its own commit, before its confirmatory runs | One freeze for all parts | The parts become ready at different times (Part C needs no pilot; LBF needed a long design phase). Freezing per part let C and A start without waiting for B, without any of them seeing confirmatory data first. |
| E3 | Part C tests **expected-value** credit (per-lane TD(0) tables, learned online) against **realised** difference rewards | Arm (c) of the v3 plan (a learned ablation critic inside the learner) | v3 theory §7 predicts expected credit cannot help a *centralised* learner. The per-lane tables are a learned expected credit with no other confound: with exact tables the arm differs from `difference` by exactly the other lanes' luck. |
| E4 | Part A: data-matched single-size control (same total number of stops) | Single-size critic with its usual 200 stops | Without matching, "mixed beats single" could be "more data beats less data". |
| E5 | LBF: own deterministic re-implementation, tested step-for-step against `lbforaging` 2.0.0 | Use the package directly | The package resolves simultaneous loads by popping a Python `set` whose order depends on memory addresses, so a cloned environment can diverge. Exact common-random-number truth needs determinism. The two agree whenever no loading agent is adjacent to two foods; the spawn rules make that impossible, and a 12-seed test confirms identical trajectories. |
| E6 | LBF critic state: agent and food levels on **one absolute scale**, plus each food's reward share | Food level divided by the episode's largest food level (first version) | The first version hid exactly what loading depends on (whether a set of agents' level sum reaches a food's level). Found while diagnosing the pilot; fixed before any confirmatory run. It alone did not rescue the critics (set L1 0.75–0.79 vs equal split 0.77–0.91), which pointed to the target, not the input (E7). |
| E7 | LBF ground truth: **removal null with heavy food** (food cap = sum of all agent levels, an `lbforaging` option) | (i) No-op null, package food cap; (ii) removal null, package cap; (iii) removal with a short horizon | (i) Under no-op the scripted planner keeps assigning the frozen agent to food, so teammates deadlock waiting for it; one frozen agent often costs *all* food. The "credit" then measures the planner's blind spot, not the agent's contribution, and is a discontinuous function of the greedy assignment. (ii) Under the package cap (sum of the 3 lowest levels) any 3 of 4 agents can lift any food, so removal leave-one-out is identically zero: degenerate by construction. (iii) Time pressure makes credit mostly luck (luck floor 0.69–0.84). With heavy food, which agents are *pivotal* for which food is the credit question, the core LBF mechanic. See the pilot table in `docs/v4/lbf_design.md`. |
| E8 | Part D (randomised start cells, deferred v3 item 2.5): random start cells for every role plus shuffled roles; bystanders never start on a coalition route | Skip it (v3's reason: shuffled roles already move start cells) | Shuffled roles move start cells only among three fixed role slots, so the travel times and the moment the lever is pulled are the same in every episode. Random start cells vary the timing, which the per-step credit depends on. Bystanders stay off the coalition's routes, as with the fixed slots, so their true credit stays zero and the episode-level test is unchanged. |
| E9 | Add a **reward-decomposed (per-food) critic** as a secondary method; keep the two-set critic primary | Make it primary; drop it | LBF's return is a sum over food items, so V = Σ_k value_k · P(food k collected) exactly (Hybrid Reward Architecture, van Seijen et al. 2017): more supervision per sample, and gone food contributes exactly zero. Pilot (5 seeds): no clear gain at v3's budget (0.34 vs 0.30), a small gain at 4× data (0.08 vs 0.14). Primary stays the set critic chosen in v3, so no method is picked on the pilot. |
| E10 | Part B pre-registers **two data budgets** (v3's 200/200 and 4×) | One budget | Random layouts make each training episode a new task, so v3's budget was not obviously enough. The pilot showed data mattering (0.30 → 0.14). Pre-registering both makes "how much data" a measured answer instead of a tuned choice. |
| E11 | Part B's 6-agent variant is **descriptive** | Pre-register it as a claim | In the pilot it was far from exact at both budgets (Shapley worse than the equal split). Claiming what the pilot already contradicts would be a set-up to fail. Its expected pattern is written down before the runs, so it is still a test of the expectation. |
| E12 | Part C: label the drawdown analysis (stability vs speed) as **post-hoc** | Fold it into C1's verdict | C1 (frozen) failed: expected credit was 4× faster than team reward at K = 8. The learning curves then showed *where* the gain comes from, and it was measured after seeing them, so it is labelled. |
