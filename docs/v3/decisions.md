# v3 decision log: what was decided, the alternatives, and why

One entry per decision, in the order taken. "Pilot" means exploratory runs on seeds 0–4 (the seeds of every earlier round), which are never used for confirmatory claims.

| # | Decision | Alternatives considered | Why |
|---|---|---|---|
| D1 | Work on branch `intervention-credit-v3` of `ManaswinHK/AFML_project`, push after each phase, one PR | Push to master; push to the fork | The user chose branch + PR. Master stays what teammates pull. |
| D2 | Python 3.12 venv, PyTorch CPU, `setuptools<81` | Python 3.15 (system) | PyTorch has no 3.15 wheels; the repo pins 3.12. Sacred imports `pkg_resources`, removed in setuptools 81. |
| D3 | Deselect `test_stas_learns_to_decompose_the_return` | Change its tolerance | It already fails at the unmodified commit in this environment (training tolerance under a newer PyTorch on ARM). Changing a test to make it pass would hide that. Documented in errata. |
| D4 | Stops are an **environment** operation (`env.stop`) plus **acting flags in the global state** | Keep the prototype's out-of-band mask appended to the critic input (round 2) | (i) Any critic that reads the state (MAPPO, QMIX mixers, COMA) can now represent stopped states with no code change, which control V2 needs. (ii) Agents' observations are unchanged, so "teammates are not told" holds under the no-op null. (iii) One source of truth for what a stopped state looks like (`stopped_state` is tested equal to what the env reports). |
| D5 | Add the **pending payout amount** to the state (Phase 0.1) | Leave partial layout as is | Without it the state is not Markov for partial events (5 vs 10 pending look identical). Tested. |
| D6 | Fix `_finish_feasible`: a pulled lever stays usable after its enabler leaves | Keep the old rule | The old rule makes finishers abandon an event that can still complete, which moves the removal-null credit from the pull to the finish (round 2). It is provably irrelevant to every earlier result (stops at t = 0 happen before any pull; tested equal on all layouts). |
| D7 | Add **role flags** (is-enabler / is-finisher per event) to the global state | Leave roles implicit in positions | Agents' own observations already carry these flags, and ECE (which reads observations) had them while state-only critics did not. Standard MARL states include unit types (SMAC). Both MLP and set critic get them, so their comparison stays information-equal. **Deviation from round 2** (Test E had no flags); the MLP numbers on shuffled roles are similar with flags (0.46 at b = 2 vs round 2's 0.41), so this did not make the MLP's job easy. |
| D8 | Make ATD, tables, uniform and the V2 controls **first-class methods in `run_data_cell`** | Keep a separate prototype pipeline (round 2's `scripts/atd`) | One scoring path for every method means identical truths, metrics and episodes. The plan asked for this (1.4). |
| D9 | Grade individual credit against the **exact truth of the method's own null** (`loo_cn` for no-op methods) | Grade everything against open-loop truth (the earlier default) | Open loop charges the open/closed gap to every estimator (floor 0.09–0.20 for the *exact* credit). No-op and removal define different games where teammates react (overlap layout: 0.26 apart), so grading a no-op critic against removal truth measures the definition, not the estimator. Both truths are reported. |
| D10 | Primary sampler **stratified** (half of stops before the last completion, half in the payout wait) | before-done (round 2), through-payout | Pilot d = 25: step r 0.998 (stratified) vs 0.887 (before-done), with no loss of episode L1. It is the same principle as DACA-GRPO's stratified masking: guarantee coverage of a stratum the default sampling misses. |
| D11 | Test a **permutation-invariant set critic** (shared per-agent encoder, one self-attention layer, sum + mean pooling) | Larger MLP; MLP with data augmentation by relabelling | Motivated by a stated symmetry (relabelling agents and the stop set together leaves W unchanged), not by "nobody combined these". Augmentation would also encode the symmetry but needs n! copies. Pilot (shuffled roles, 200 stops): L1 0.004 (b = 2) and 0.006 (b = 4) vs MLP 0.46 and 0.86. |
| D12 | Test **active intervention design** (bootstrap-ensemble disagreement at the stop's start state) | None, or uncertainty over full trajectories | Round 2 showed accuracy depends heavily on *which* stops are in the data; the read-out queries only stop start states. Pilot: no reliable gain (MLP b = 2 perm 0.46 → 0.39; but worse at d = 0, b = 4 crit: 0.02 → 0.16; set critic already at the floor). **Not pre-registered as a claim**; reported as an exploratory negative result. |
| D13 | **Control V2** trains MAPPO and QMIX on exactly the same 200 stopped episodes as `atd` and reads them out two ways | Skip V2 | It is the decisive test of "better data or better read-out". Smoke (d = 25, b = 2): the standard one-step read-outs stay poor with the new data (MAPPO 1.85, QMIX 1.10), while the masked read-outs of the same critics improve (0.32, 0.78). |
| D14 | **Commitment split** read-out (`atd_struct`) and an **expected-credit floor** (`floor_expected`) | Declare the partial layout "unsolved" | The partial layout's realised credit flips with exploration luck (a third of test episodes have one finisher completing alone). A state critic can only know expected credit. The floor (mean realised truth as the prediction) measures how close any expected-credit estimator can get; the structural read-out removes the luck term that κ carries. Tiny-cell check: κ 0.45, structural 0.25, floor 0.19. |
| D15 | Phase 3 arms: **team**, **team_vector**, **difference** (shadow copies); plan arm (c), learned ablation-TD credit, kept as a stretch arm | Run (c) as planned | Theory §7: with exact critics, (c)'s per-agent advantage *equals* the team TD error, so (c) can only differ from (a) by critic error. `team_vector` instead controls the per-agent-reward code path, so a (b) vs (a) gap cannot be plumbing. |
| D16 | Phase 3 uses **EPyMARL's IPPO** unmodified, with an adapter `reward_mode` | Write a lean PPO | A standard, citable implementation. EPyMARL's PPO learner already supports per-agent rewards. Feasibility: one lane solved (98% test success) by 120k steps in about 80 s. |
| D17 | Add a **zero-shot size-transfer** test of the set critic (train n = 5, read out n = 7, and back) | No transfer test | Only a size-independent critic can attempt it. It is a sharp test of whether the critic learned the structure ("a stopped enabler before its pull loses the event") rather than a lookup table. |
| D18 | Phase 4 reduced to **dropout-trained MAPPO critic as ablation critic** (4.1/4.2) | Full Phase 4 incl. LBF | One-week deadline on one Mac. 4.1/4.2 directly test whether credit comes "for free" from robustness training; LBF needs new truth machinery. |
